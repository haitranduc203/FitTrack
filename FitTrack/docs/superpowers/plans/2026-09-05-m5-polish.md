# M5 Polish Implementation Plan

> **Goal:** Complete Milestone M5 Polish across all 10 application screens and 10 polish dimensions, guaranteeing rock-solid stability, accessibility, dark theme consistency, and 84+ device test passes within 360 seconds.

---

## Task Breakdown & Commit Plan

### Task 1: Review Loading States
- **Commit:** `fix(ui): polish loading states`
- **Scope:**
  - Audit loading across Startup, Exercise List, Exercise Detail, Workout List, Workout Editor, Active Workout, History, History Detail, Settings.
  - Retain previous content when refreshing/retrying where appropriate (prevent disruptive full-screen flashing).
  - Ensure all write/action triggers have pending states (`isSaving`, `isCompletingSet`, `isFinishing`, `isDeleting`, `isTogglingFavorite`) with double-tap protection.
  - Update and add Compose `@Preview` coverage for loading states across all screens.
  - Run targeted unit tests and assembleDebug.

### Task 2: Review Empty States
- **Commit:** `fix(ui): polish empty states`
- **Scope:**
  - Disambiguate empty states:
    - Empty database exercises vs Search/Filter no match vs Favorites filter empty.
    - Workout list empty: guidance to tap `+` to create.
    - History list empty: guidance on completed workouts.
    - Exercise Detail missing ID (`isMissing`): dedicated "Exercise not found" card with Back button (stop reusing generic `empty_exercises`).
    - History Detail missing ID (`isMissing`): dedicated "Workout session not found" card with Back button (stop reusing generic `empty_history`).
    - Active Workout missing session (`isMissing`): dedicated "Session not found" card with Back button (fix indefinite progress indicator bug when session is null).
  - Add new string resources in `strings.xml`.
  - Add previews for empty and missing states.
  - Run targeted unit tests.

### Task 3: Review Error and Retry States
- **Commit:** `fix(ui): polish error and retry states`
- **Scope:**
  - Audit error states across all ViewModels and screens.
  - Recoverable errors must show clear user-friendly localized messages and a prominent "Retry" action.
  - Retain last successful content during background refresh failures.
  - Ensure `CancellationException` and `Error` are never swallowed.
  - Never allow ViewModels to get stuck in loading/saving/deleting state on error.
  - Add unit tests for failure, retry, and cancellation paths.

### Task 4: Add Transient Snackbar Feedback
- **Commit:** `feat(ui): add transient snackbar feedback`
- **Scope:**
  - Implement one-shot transient feedback for short action outcomes:
    - Workout template saved successfully.
    - Workout template deleted successfully.
    - Favorite toggle status / failure notification.
    - Action failures that do not warrant full-screen error cards.
  - Use `SnackbarHostState` in screen scaffolds.
  - Use `Channel<UiText>(Channel.BUFFERED)` in ViewModels, collected in Compose via `LaunchedEffect`.
  - Guarantee single consumption (no replay on Activity recreation).
  - Zero boolean state flags, zero unmanaged coroutine scopes, zero GlobalScope.
  - Add targeted unit/UI tests verifying single-consumption semantics.

### Task 5: Destructive Action Confirmations
- **Commit:** `feat(ui): confirm destructive actions`
- **Scope:**
  - Audit irreversible operations:
    - Workout template deletion: verify and polish existing `AlertDialog` in `WorkoutListScreen` (title, message, Delete button disabled when deleting, Cancel button, outside dismiss).
    - Workout Editor discard: when navigating back with unsaved changes, prompt with `AlertDialog` (Discard / Keep Editing).
    - Active Workout finish: double-submit guard (`isFinishing`) verified; persistence is constructive.
  - Add localized strings for discard confirmation.
  - Add ViewModel and UI tests for confirmation dialogs, cancel dismissal, and double-tap prevention.

### Task 6: Review Dark Theme Consistency
- **Commit:** `fix(theme): polish dark theme consistency`
- **Scope:**
  - Audit all screens and components in both Light and Dark themes.
  - Eliminate hardcoded color constants, raw hex codes, and non-semantic alpha blends.
  - Use semantic `MaterialTheme.colorScheme` tokens (`surface`, `surfaceVariant`, `onSurface`, `primaryContainer`, `errorContainer`, etc.).
  - Check cards, dialogs, snackbars, text fields, filter chips, radio options, and the rest timer progress bar.
  - Add `@Preview` for Dark Mode alongside existing Light Mode previews for all core screens.

### Task 7: Complete Compose Semantics and Accessibility
- **Commit:** `fix(accessibility): complete compose semantics`
- **Scope:**
  - Touch target audit: ensure all interactive elements meet the minimum 48x48 dp standard.
  - Content description audit: descriptive resources for actionable icons; `contentDescription = null` for decorative icons.
  - Semantics audit: mark headings with `Modifier.semantics { heading() }`; expose selected/filter state via `selected` semantics.
  - Form fields: ensure clear labels and keyboard actions.
  - Verify TalkBack traversal order and avoid redundant speech.
  - Add Compose semantics UI assertions in test suite.

### Task 8: Preserve UI State Across Configuration Recreation
- **Commit:** `fix(lifecycle): preserve ui state across recreation`
- **Scope:**
  - Test state preservation via `ActivityScenario.recreate()`:
    - Exercise list search query & filter selections.
    - Workout editor input fields and selected exercise list.
    - Active workout input fields, elapsed timer, and rest timer deadline.
    - Theme selection in Settings.
    - Transient snackbars do not re-fire on recreate.
  - Verify `SavedStateHandle` and `rememberSaveable` are used appropriately.
  - Add unit and instrumentation tests for configuration recreation without real time delays.

### Task 9: Optimize Exercise List Rendering and Filtering
- **Commit:** `perf(exercises): optimize list rendering and filtering`
- **Scope:**
  - Benchmark and audit the 1,324-exercise list rendering.
  - Add `contentType = { "exercise_item" }` to `LazyColumn.items`.
  - Add `distinctUntilChanged()` on filter flows in `ExerciseListViewModel` to prevent redundant recompositions.
  - Verify in-memory query filtering performance and memory allocations.
  - Test rapid query/filter changes and cancellation.

### Task 10: Remove Unused Code and Dependencies
- **Commit:** `chore: remove unused code and dependencies`
- **Scope:**
  - Use CodeGraph and ripgrep to audit unused imports, dead helpers, and unreferenced dependencies.
  - Safely remove confirmed dead code.
  - Preserve all testing dependencies, reflection/Hilt targets, Room entities, and preview code.
  - Verify clean build, unit tests pass, and full test suite passes.

---

## Verification Gates per Task
1. Targeted unit tests pass.
2. Targeted UI/instrumentation tests pass (where applicable).
3. `:app:assembleDebug` succeeds with exit code 0.
4. `git diff --check` passes with zero whitespace/formatting issues.
5. Exactly one atomic commit created per task.

## Final Verification Protocol
1. Python unit tests: `python -m unittest discover -s tools -p "test_*.py" -v`
2. Full build and unit tests: `.\gradlew.bat :app:clean :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug --no-daemon`
3. Two consecutive full device test runs (84+ tests): `.\gradlew.bat connectedDebugAndroidTest --no-daemon` (each < 360s, exit code 0, complete XML).
4. Documentation update: `FitTrack_Project_Plan/phase-results/PHASE_5_RESULT.md` and `FitTrack_Project_Plan/06_TASK_BACKLOG.md`.
